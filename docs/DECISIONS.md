# Decisions

Architecture decision records (ADRs) and the **contract seed** — the shared names every document and every agent
must use. Edited only by the coordinator. When a doc and this file disagree, this file wins until the coordinator
resolves the conflict.

## ADRs

| # | Decision | Why | Consequences |
|---|---|---|---|
| ADR-001 | pnpm 11 monorepo: `apps/web`, `apps/server`, `packages/shared`, `packages/plugin-sdk` | One language (TypeScript) and shared contracts across web, server and plugins | All pnpm settings live in `pnpm-workspace.yaml`; internal packages export TS source |
| ADR-002 | Backend = Hono on Node (`@hono/node-server`) | Small, fast, streams web `Response`s from the AI SDK natively, serves the built SPA | Production is one process on one port (:8787) |
| ADR-003 | LLM layer = Vercel AI SDK v7 with official provider packages | Official providers exist for every required vendor (incl. Moonshot, Alibaba, Z.ai, MiniMax); `LanguageModelV4` spec lets plugins add providers | Follow v7 names (`instructions`, `isStepCount`, `toolApproval`, `onEnd`); verify in installed types |
| ADR-004 | Storage = SQLite via Drizzle ORM 0.45 + `@libsql/client` | Zero-ops self-hosting; libsql avoids native build scripts | Migrations generated by drizzle-kit, applied with `migrate()` at boot |
| ADR-005 | Frontend = Nuxt 4 SPA (`ssr: false`) + shadcn-vue + Tailwind 4 | User requirement; SPA fits an authenticated app served by the API process | `nuxt generate` → `.output/public`, served with `200.html` fallback |
| ADR-006 | Dark theme default via `@nuxtjs/color-mode` (`preference` and `fallback` = `dark`) | User requirement | E2E asserts `html.dark` even when the OS prefers light |
| ADR-007 | Chat UI built from AI Elements Vue (copied, prefix `Ai`) + custom pieces; markdown via markstream-vue behind `Markdown.vue` | AI Elements already handles AI SDK part states (approvals, reasoning, attachments); copied source removes runtime dependency risk | vue-stream-markdown pinned `^1` only while copied components import it |
| ADR-008 | Plugins: declarative (`plugin.json` only) and code (single ESM entry, in-process) | Declarative covers most custom providers safely; code covers tools/hooks/special providers | Code plugins need explicit trust (sha256 pinning), guard timeouts, safe mode; future: child-process isolation |
| ADR-009 | Built-in providers are one builtin plugin (`core-providers`) using the public SDK | Dogfooding proves the plugin API is sufficient | Individual providers can be disabled; the plugin cannot be uninstalled |
| ADR-010 | Brand icons from `@lobehub/icons-static-svg`, served only by the server | One icon pipeline for builtins and plugins; MIT license; full slug catalog for the wizard | Mono icons rendered via CSS mask, color icons via `<img>`; never inline SVG with `v-html` |
| ADR-011 | Model metadata from a bundled models.dev snapshot + live provider listings | Live `/models` endpoints return ids only; models.dev adds limits, capabilities, pricing | Weekly refresh into `data/cache` unless `HF_OFFLINE=1` |
| ADR-012 | Single-user security model: optional password, HMAC session cookie, AES-256-GCM secrets, loopback bind without password | Personal self-hosted deployment (user decision) | Multi-user accounts are out of scope for v1 |
| ADR-013 | TypeScript pinned to ~6.0.3 | TS 7 breaks `.vue` files importing prop types (shadcn-vue) | `catalog` + `overrides` in `pnpm-workspace.yaml`; checked at every gate |
| ADR-014 | English-only repository enforced by `pnpm check:english` (fails on any Cyrillic) | User requirement | Runs in `pnpm check` and CI |
| ADR-015 | Harness scope v1 = chat + tool-calling agent loop; no built-in filesystem/shell tools | User decision | Tools come from plugins (`core-tools`, MCP, user plugins) |
| ADR-016 | Build with parallel sub-agents in waves: contracts first, single-owner paths, frozen shared files, CCR protocol, gate + checkpoint commit per wave on `main` | User asked for many sub-agents; ownership prevents conflicting edits | Coordinator alone runs package managers, CLIs, dev servers, git writes |
| ADR-017 | Fresh authentication for sensitive operations when a password is set: installing a code plugin (or a declarative plugin with a stdio MCP server), trusting a plugin, changing the password | An XSS or stolen session must not silently lead to code execution on the server | Endpoints accept a short-lived fresh-auth proof (see API.md); writing code files (`PUT`/`DELETE /plugins/:id/files/*` on a code plugin), `POST /plugins/:id/build` and `POST /plugins/:id/reload` of a code plugin also require fresh auth (a 10-minute window, so the editor asks at most once per window); after such a fresh-auth write, a plugin with source `created` re-pins its trust hash automatically; files changed on disk require re-trust (except linked folders trusted by path) |
| ADR-018 | Package direction: `plugin-sdk` depends on `shared`. Zod schemas for `PluginManifest`, `ModelInfo`, `CredentialField`, `SettingsSchema` and all enums live in `shared`; `plugin-sdk` re-exports them and adds the runtime plugin API types + `definePlugin` | Shared API DTOs embed these schemas; one direction avoids a cycle | Contracts are written by one agent (C1+C2 merged) |
| ADR-019 | Message ids: user message ids are generated by the client (`createMessageId`) so edit/regenerate can reference them; assistant message ids are generated by the server | AI SDK `useChat` creates user message ids on the client | Server validates the `msg_` format and never trusts client ids for assistant messages |
| ADR-020 | v1 has no bulk data export/import/delete endpoints; per-chat export exists | Keep v1 scope tight | Listed in the ROADMAP backlog |
| ADR-021 | `messages.search_text` stores NFC-normalized, lowercased plain text of message parts | SQLite `LIKE`/`lower()` only folds ASCII; normalizing on write makes search case-insensitive for every script | Search terms are normalized the same way; stored text is not for display |
| ADR-022 | Single branch: all development happens on `main` | The v1 rebuild ran on a temporary `harness-forge` branch that became `main`; the previous app's history was removed at the user's request | Commit to `main` after green gates; CI runs on every push to `main`; push/force-push only when the user asks |

## Contract seed

### Packages

`harness-forge` (root, private) · `@harness-forge/shared` · `@harness-forge/plugin-sdk` · `@harness-forge/server` ·
`@harness-forge/web`.

### Ports and processes

| Port | Use |
|---|---|
| 3000 | `nuxt dev` (coordinator) |
| 8787 | server dev + production (`HF_PORT`) |
| 8899 | `pnpm start:e2e` (coordinator) |
| 879k / 889k | agent slot k: own server / own e2e server |

### Environment variables

| Name | Default | Meaning |
|---|---|---|
| `HF_PORT` | `8787` | server port |
| `HF_HOST` | `127.0.0.1` | bind address; a non-loopback host requires `HF_PASSWORD` or `HF_INSECURE=1` |
| `HF_DATA_DIR` | `./data` | data directory (resolved against the repo root in dev) |
| `HF_PASSWORD` | unset | enables login; overrides a password stored in settings |
| `HF_MASTER_KEY` | unset | base64 32-byte master key; otherwise `data/secret.key` is generated (mode 0600) |
| `HF_MOCK_PROVIDER` | unset | `1` registers the dev-only `mock` provider |
| `HF_SAFE_MODE` | unset | `1` loads builtin plugins only |
| `HF_PLUGIN_WATCH` | unset | `1` hot-reloads code plugins on file change |
| `HF_OFFLINE` | unset | `1` disables network refresh of the models.dev snapshot |
| `HF_INSECURE` | unset | `1` allows a non-loopback bind without a password |
| `HF_API_TARGET` | `http://localhost:8787` | web dev proxy target |
| `HF_WEB_DIR` | `apps/web/.output/public` | directory of the built SPA served in production |
| `<VENDOR>_API_KEY` | unset | provider key fallbacks (see PROVIDERS.md) |

### Data directory

```
data/
  harness.db            SQLite (WAL)
  secret.key            master key when HF_MASTER_KEY is unset (0600)
  plugins/<id>/         installed plugins (plugin.json, entry, assets)
  plugins/.staging/     in-progress installs
  files/<aa>/<sha256>   uploaded attachments (content-addressed)
  cache/                models.dev snapshot refreshes, misc caches
```

### Identifiers

- **Model ref**: `providerId:modelId`, split on the first `:`. Never in URL paths.
- **Plugin id**: `^[a-z0-9](?:[a-z0-9-]{0,38}[a-z0-9])?$`, equals its directory name. Reserved: `core-*`, `mock`,
  and every builtin provider id.
- **Builtin plugin ids**: `core-providers`, `core-tools`, `core-commands`, `core-mcp`, `mock` (only with
  `HF_MOCK_PROVIDER=1`).
- **Builtin provider ids** (models.dev keys): `anthropic`, `openai`, `google`, `xai`, `deepseek`, `moonshotai`,
  `alibaba`, `zai`, `minimax`, `mistral`, `groq`, `openrouter`, `ollama`; dev-only `mock`.
- **Plugin provider ids**: `<pluginId>` or `<pluginId>-<suffix>`.
- **Tool name**: `^[a-zA-Z0-9_-]{1,64}$`, globally unique. MCP tools: `mcp__<serverId>__<tool>` (truncated with a
  short hash when longer than 64).
- **Command name**: `^[a-z][a-z0-9-]{0,31}$` (typed as `/name`). Client-only commands: `/new`, `/model`, `/effort`,
  `/mode`, `/help`.
- **Chat id**: uuidv7 generated by the client for new chats. **Message id**: `msg_` + 16 chars; user messages get
  client-generated ids (`createMessageId`), assistant messages get server-generated ids (ADR-019). **File id**:
  `file_` + 16 chars. **Session cookie**: `hf_session`.
- **Secret scopes**: `provider:<id>`, `plugin:<id>`, `mcp:<id>`, `auth`.

### Enumerations

- `ToolMode` = `off | ask | auto` (UI label: permission mode; default `ask`).
- `ReasoningEffort` = `auto | off | low | medium | high | max` (`auto` sends nothing).
- `ToolPolicy` = `safe | ask | always`; tool pref override = `allow | ask | deny`.
- Plugin `kind` = `declarative | code`; plugin `source` = `builtin | created | zip | npm | url | link | copy`;
  plugin `state` = `disabled | untrusted | incompatible | loading | active | error`.
- Provider status = `connected | not_configured | env | error`.
- Declarative `apiFormat` = `openai-chat | openai-responses | anthropic | google`.

### Error envelope

`{ error: { code, message, status?, providerId?, retryAfterMs?, action?, details? } }` with `code` one of
`validation_error, unauthorized, forbidden, not_found, conflict, payload_too_large, provider_not_configured,
auth_invalid, rate_limited, model_not_found, context_overflow, provider_unreachable, provider_error, plugin_error,
internal_error, not_implemented` (501, used by Phase 0 route stubs). The envelope `status` is the upstream
provider status when relevant; the HTTP status is derived from `code` (`errorStatusByCode` in shared; e.g.
`auth_invalid` → 502 so a bad provider key never redirects to login). `action` one of `configure-provider | refresh-models | login | retry`.

### Server-sent events (`GET /api/events`)

`chat.created`, `chat.updated` (incl. title), `chat.deleted`, `run.started`, `run.finished`, `provider.changed`,
`catalog.changed`, `plugin.changed`, `plugin.log`. Payload: `{ type, data, at }`. `run.finished` data includes
`awaitingApproval: boolean` (drives the amber sidebar dot; also persisted as `chats.pending_approval`).

### Chat request (`POST /api/chat`)

`{ chatId, message, trigger: 'submit-message' | 'regenerate-message', messageId?, modelRef, reasoningEffort,
toolMode }` — only the last UI message is sent; the server owns history.
Message metadata: `{ modelRef, startedAt, finishedAt?, durationMs?, reasoningMs?, usage?, costUsd?, finishReason?,
aborted?, error?, command? }`.

### Global settings keys (`GET/PUT /api/settings`)

`displayName`, `defaultModelRef`, `titleModelRef`, `instructions`, `sendKey` (`enter | mod-enter`),
`defaultToolMode`, `defaultReasoningEffort`, `maxSteps` (20), `altShortcuts` (true), `showThinking` (false),
`density` (`comfortable | compact`), `readingFont` (`sans | serif`), `textSize` (`sm | md | lg`).
The theme itself is stored client-side by `@nuxtjs/color-mode` (key `hf-color-mode`) so it applies before boot.

### Database tables

`settings`, `secrets`, `provider_configs`, `model_cache`, `model_prefs`, `chats`, `messages`, `usage`, `plugins`,
`plugin_settings`, `plugin_kv`, `tool_prefs`, `mcp_servers`, `files` — columns in `docs/ARCHITECTURE.md`.

### Icons

Manifest `icon`: `lobe:<slug>` or a relative file path inside the plugin. URLs: `/api/icons/lobe/<slug>`,
`/api/plugins/<id>/icon`. DTO: `icon: { color?: string; mono?: string } | null`.

### UI query parameters

Plugins list filter: `/plugins?filter=all|providers|tools|mcp|commands|disabled` (not `kind`, which is the plugin
kind enum).

### Mock provider (dev only)

Models `mock:echo`, `mock:reasoning`, `mock:tool-approval`, `mock:error`; the approval tool is named
`mock_approval_tool` (policy `ask`). Behavior is specified in PROVIDERS.md.

### Example plugins

`examples/plugins/<id>/` where the folder name is the plugin id: `lmstudio`, `together-ai`, `dice-roller`,
`echo-provider`, `mcp-everything`.

### Health

`GET /api/health` → `{ ok, version, node, uptimeSec, safeMode, pluginApiVersion, versions: { ai, hono, nuxt? } }`
(used by Settings → About and the safe-mode banner).

### Tool output cap

A tool output whose serialized JSON exceeds `LIMITS.toolOutputBytes` (64 KB) is replaced by the server with
`{ truncated: true, originalBytes: number, preview: string }` (`preview` = the first 64 KB of the serialized JSON).
The web shows "Truncated by server" for any object output with `truncated: true`.

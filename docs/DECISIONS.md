# Decisions

Architecture decision records (ADRs) and the **contract seed** — the shared names every document and every agent
must use. Edited only by the coordinator. When a doc and this file disagree, this file wins until the coordinator
resolves the conflict.

| ADR-040 | Context compaction (Phase 9): `/compact [focus]` (a reserved harness command) and automatic compaction replace older context with a model-written summary stored as a `data-compaction` part on the message path; for the model, the latest marker on the path replaces everything before it (positional: earlier messages and the earlier parts of its own message; `keep: last-user` keeps the turn's user message); automatic compaction runs before every model call (`prepareStep`, step 0 included) once the estimate passes 80 % of the context window, so long agent runs compact in place | Silently dropping old turns lost context the agent needed (user decision; Claude Code parity) | Stored messages are never rewritten and stay visible (dimmed); a branch above a marker ignores it (ADR-023); settings `autoCompact` (on) and `compactModelRef` (null = the chat model); a failed or disabled compaction falls back to the old trimming (notices `compaction-failed` / `context-trimmed`); at most 10 compactions per run; usage purpose `compact`; the summary is in the Markdown export, not in share pages or the search text; the summarizer reads a text rendering of the transcript (tool results capped) |

| ADR-042 | Steer queue and file mentions (Phase 9): a message sent while a run is active joins an in-memory per-chat queue (`/chat/:id/queue`, SSE `queue.changed`); at the next step boundary the run takes every queued message and the model sees it as a user message (stored as a `data-steer` part inside the running reply); a message still queued when the run completes becomes the next turn, started by the server; `@` in the composer of a project chat searches the project's files (`GET /projects/:id/files`, an in-memory index that respects `.gitignore` and leaves secret-looking paths out) and attaches the picked file as an upload snapshot (`POST /projects/:id/files/attach`) | Users could not correct or extend a running agent and copied files in by hand (user decision; Claude Code parity) | The chat request body is unchanged (mentions are attachments); the queue is lost on restart (documented), holds ≤ 10 messages of ≤ 256 KB, is emptied by Stop (the messages return to the composer), by chat deletion, key rotation, shutdown and an aborted or failed run; server commands (incl. `/compact`) are never steered; while an approval is pending, queued messages wait for the next run; the model history splits a reply at its steers; share pages show steers as user messages; attachments ≤ 5 MiB, `.git` and secret-looking paths refused; conflict reasons `run-idle`, `queue-full` |

| `<VENDOR>_API_KEY` | unset | provider key fallbacks (see PROVIDERS.md) |

CLI-only variable: `HF_NEW_MASTER_KEY` (base64 32-byte key, read only by the `rotate-key` CLI when the current key
comes from `HF_MASTER_KEY`; ADR-034).

Test-only variables: `HF_LIVE` (`1` enables the live provider suite, `pnpm test:live`), `HF_LIVE_PROVIDERS` (comma
list of provider ids to run), `HF_LIVE_MAX_COST_USD` (budget of one live run), `HF_TEST_REQUIRE_WEB_BUILD` (`1`
turns the skipped built-page CSP test into a failure when the web build is missing), `E2E_SCREENSHOTS` (`1` runs the
`@screenshots` Playwright spec), `HF_LIVE_MEDIA` (`1` adds the image and voice checks to the live suite; Phase 6), `HF_TEST_FILE_SWEEP_DELAY_MS`
(1000 – 86400000: replaces the automatic file sweep's boot delay and hourly check; honored only with
`HF_MOCK_PROVIDER=1`, otherwise ignored with a boot warning; Phase 8, ADR-039).

### Identifiers

- **Model ref**: `providerId:modelId`, split on the first `:`. Never in URL paths.
- **Plugin id**: `^[a-z0-9](?:[a-z0-9-]{0,38}[a-z0-9])?$`, equals its directory name. Reserved: `core-*`, `mock`,
  and every builtin provider id.
- **Builtin plugin ids**: `core-providers`, `core-tools`, `core-commands`, `core-mcp`, `core-workspace` (Phase 7),
  `core-agent` (Phase 9), `mock` (only with `HF_MOCK_PROVIDER=1`).
- **Builtin provider ids** (models.dev keys): `anthropic`, `openai`, `google`, `xai`, `deepseek`, `moonshotai`,
  `alibaba`, `zai`, `minimax`, `mistral`, `groq`, `openrouter`, `ollama`; dev-only `mock`.
- **Plugin provider ids**: `<pluginId>` or `<pluginId>-<suffix>`.
- **Tool name**: `^[a-zA-Z0-9_-]{1,64}$`, globally unique. MCP tools: `mcp__<serverId>__<tool>` (truncated with a
  short hash when longer than 64).
- **Builtin tool names**: `current_time`, `web_fetch`, `generate_image` (Phase 6, ADR-028) from `core-tools`;
  `read_file`, `list_directory`, `find_files`, `search_files`, `write_file`, `edit_file`, `shell` from `core-workspace`
  (Phase 7, ADR-032); `todo_write`, `exit_plan_mode`, `task` from `core-agent` (Phase 9, ADR-041 / ADR-043).
- **Plugin API version** (`PLUGIN_API_VERSION`): `1.3.0` (Phase 9, additive: `ToolMode` `plan`, a tool's `execute` returns its output
  (or a promise of it) or is an async generator whose yields are preliminary outputs); `1.2.0` (unchanged in Phase 8; Phase 7, additive: `ToolCallContext.workspace`,
  `ToolDefinition.workspace`, `ImageGenerateResult.modelName`); `1.1.0` (Phase 6) added the image, transcription and
  speech factories, `imageParams`, `transcriptionOptions`, `ctx.images`.
- **Command name**: `^[a-z][a-z0-9-]{0,31}$` (typed as `/name`). Client-only commands: `/new`, `/model`, `/effort`,
  `/mode`, `/help`. Harness commands (run by the server, reserved, listed by `GET /commands`): `/compact` (Phase 9,
  ADR-040).
- **Chat id**: uuidv7 generated by the client for new chats. **Message id**: `msg_` + 16 chars; user messages get
  client-generated ids (`createMessageId`), assistant messages get server-generated ids (ADR-019). **File id**:
  `file_` + 16 chars. **Session cookie**: `hf_session`.
- **Project id** (Phase 7): `prj_` + 16 chars; the project path is the canonical realpath of its folder (unique).
- **Shell rule id** (Phase 8): `srl_` + 16 chars. **Change batch id** (Phase 8): `wcb_` + 16 chars (one revert, rewind
  or undo; ADR-036).
- **Share id**: `shr_` + 16 chars. **Share token** (`^[0-9A-Za-z]{16}[\w-]{22}$`): the 16-char share id suffix + the
  first 22 base64url chars of `HMAC-SHA256(subkey 'share', 'harness-forge/share/v1:' + shareId)`; never stored
  (ADR-025). Share page URL: `/share/<token>`.
- **Message tree** (ADR-023): `messages.parent_id` (null = a first message; siblings share a parent),
  `chats.active_leaf_id` (last message of the shown path; null = empty chat); `seq` = creation order;
  `messages.selected_child_id` (ADR-030: the child last shown under a message, a hint; null or a missing child = the
  latest leaf).
- **Secret scopes**: `provider:<id>`, `plugin:<id>`, `mcp:<id>`, `auth`.
- **Keyring subkeys** (HKDF of the master key): `encryption`, `session`, `approval`, `share`. Key state (Phase 7,
  ADR-034): internal setting `_keys` = `{ version, check, rotatedAt }` (`check` = HMAC-SHA256 of the `encryption`
  subkey over `harness-forge/key-check/v1`); `secrets.key_version` equals `_keys.version` after a rotation. Internal
  setting `_files` = `{ lastCleanup, lastAutoSweep? }` (ADR-035; `lastAutoSweep = { at, status: done | skipped |
  failed, reason: plugin-data-limit | error | null, files, diskBytes }`, ADR-039).

### Enumerations

- `ToolMode` = `off | ask | edits | plan | auto` (UI label: permission mode; default `ask`; `edits` = "Accept edits",
  Phase 7; `plan` = "Plan", Phase 9). Workspace access (`ToolDefinition.workspace`) = `read | write | execute`.
- `ReasoningEffort` = `auto | off | low | medium | high | max` (`auto` sends nothing).
- `ToolPolicy` = `safe | ask | always`; tool pref override = `allow | ask | deny`.
- Plugin `kind` = `declarative | code`; plugin `source` = `builtin | created | zip | npm | url | link | copy`;
  plugin `state` = `disabled | untrusted | incompatible | loading | active | error`.
- Provider status = `connected | not_configured | env | error`.
- Declarative `apiFormat` = `openai-chat | openai-responses | anthropic | google`.
- Model `kind` = `chat | embedding | image | audio | transcription | speech | other` (`transcription` and `speech`
  added in Phase 6). Usage `purpose` = `chat | title | image | transcription | speech | compact | subagent` (the last two: Phase 9).
- Conflict `details.reason` (409) = `run-active | busy | exists | only-version | env-key | key-mismatch` (the last
  two: Phase 7 key rotation). Phase 8 adds no reason (rewind / revert use `run-active`, a stale revert uses the
  existing `stale` reason of `errors.ts`, a duplicate shell rule `exists`). Phase 9 adds `run-idle` (a queued message
  for a chat with no run and no pending approval) and `queue-full`.
- Workspace change `kind` (Phase 8) = `edit | revert | rewind | undo | shell | untracked`; before-state = `missing |
  stored | too-large | evicted`; `workspace.changed` source = `tool | rewind | revert | undo`; change view source =
  `chat | git`; conflict handling = `skip | force`; `fileSweep` = `off | daily | weekly`.
- Phase 9: todo `status` = `pending | in_progress | completed`; `task` type = `explore | general`; task `status` =
  `queued | running | completed | failed | aborted | limit`; task step `state` = `running | done | error | denied`;
  compaction `trigger` = `manual | auto`, `keep` = `none | last-user`; queue removal `reason` = `delivered | started |
  cancelled | stopped | failed`; `run.started` `origin` = `request | queue`.

### Error envelope

`{ error: { code, message, status?, providerId?, retryAfterMs?, action?, details? } }` with `code` one of
`validation_error, unauthorized, forbidden, not_found, conflict, payload_too_large, provider_not_configured,
auth_invalid, rate_limited, model_not_found, context_overflow, provider_unreachable, provider_error, plugin_error,
internal_error, not_implemented` (501, used by Phase 0 route stubs). The envelope `status` is the upstream
provider status when relevant; the HTTP status is derived from `code` (`errorStatusByCode` in shared; e.g.
`auth_invalid` → 502 so a bad provider key never redirects to login). `action` one of `configure-provider | refresh-models | login | retry`.

### Server-sent events (`GET /api/events`)

`chat.created`, `chat.updated` (incl. title; data = the chat summary + `activeLeafId`, ADR-030), `chat.deleted`, `run.started`, `run.finished`, `provider.changed`,
`catalog.changed`, `plugin.changed`, `plugin.log`; Phase 7: `project.changed` (`{ id, project }`, `project` null =
deleted) and `key.rotated` (`{ keyVersion, rotatedAt, chatIds }`; every event stream closes after it); Phase 8:
`workspace.changed` (`{ projectId, chatId, batchId, source, paths }`, ADR-036; tool edits coalesced to at most one
event per second per chat); Phase 9: `queue.changed` (`{ chatId, items, removed? }`, ADR-042) and `run.started` gains
`origin?` and `userMessageId?` (a turn the server started from the queue). Payload: `{ type, data, at }`. `run.finished` data includes
`awaitingApproval: boolean` (drives the amber sidebar dot; also persisted as `chats.pending_approval`).

### Chat request (`POST /api/chat`)

`{ chatId, message, trigger: 'submit-message' | 'regenerate-message', parentId?, messageId?, modelRef,
reasoningEffort, toolMode, imageOptions?, projectId? }` — only the last UI message is sent; the server owns history. `parentId` (a message id or
`null`) only with `submit-message` and a user message: the new message's parent (an edit = a new user message whose
parent is the edited message's parent); omitted = the chat's active leaf. `messageId` only with `regenerate-message`
(the reply to regenerate or the user message to answer). A user message sent with `messageId` is rejected (ADR-023).
`imageOptions` (`{ n?, aspectRatio?, editPrevious? }`, ADR-028) only with an image model or a chat model with image
output (`n` / `editPrevious` image models only). `projectId` (Phase 7) is honored only when the request creates the chat. Message metadata: `{ modelRef, startedAt, finishedAt?, durationMs?,
reasoningMs?, usage?, costUsd?, finishReason?, aborted?, error?, command?, image? }`. Phase 9: the request is unchanged
(file mentions are attachments, ADR-042); `POST /chat/:id/stop` returns the queued messages it dropped (`dropped`).

### Tool output cap

A tool output whose serialized JSON exceeds `LIMITS.toolOutputBytes` (64 KB) is replaced by the server with
`{ truncated: true, originalBytes: number, preview: string }` (`preview` = the first 64 KB of the serialized JSON).
The web shows "Truncated by server" for any object output with `truncated: true`.
